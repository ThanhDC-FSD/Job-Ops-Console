## AI-Assisted Development Workflow
I use GitHub Copilot, OpenCode, and OpenAI Codex daily. The workflow is transferable across modern coding assistants, so the tool can change without changing the engineering standard.

1. **Define context and constraints**
   I start by stating the goal, the existing code, the risk boundaries, and the constraints that matter. That keeps the assistant focused on the actual task instead of broadening into speculative output.

2. **Generate or explore implementation options**
   I use the assistant to explore options, draft implementation paths, and surface trade-offs quickly. This is useful for implementation support, code exploration, and troubleshooting.

3. **Review AI-generated code critically**
   I check the generated work for correctness, maintainability, and fit with the surrounding system. AI-assisted code review still needs human judgment, especially when the change affects structure, reliability, or long-term support.

4. **Validate with tests, logs, or controlled execution**
   I verify behavior with the safest available signal: tests, logs, or controlled execution. The point is to prove that the code behaves as expected, not just that it looks plausible.

5. **Refine and integrate into maintainable code**
   I tighten the implementation, clean up the edges, and integrate the result into code that the team can maintain. Final design and production quality stay under human ownership.
